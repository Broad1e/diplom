# Работа над платформой

Перед изменениями прочитай [требования](docs/REQUIREMENTS.md), [архитектуру](docs/ARCHITECTURE.md), [решения](docs/DECISIONS.md) и [план реализации](docs/ROADMAP.md). Уточни статус решения по затронутой части системы. Существенные изменения требований, контрактов и архитектуры согласуй с владельцем проекта. После согласования обнови связанные документы.

## Правила разработки

- Проверяй изменения через штатные точки входа. Для агента целевая ОС Windows. Основной сценарий сбора и демонстрации не должен требовать запуска отдельной виртуальной машины.
- Соблюдай единый формат измерений. Изменения идентификаторов, единиц, трактовки времени и правил повторной записи проверяй у отправителя, в хранилище и у потребителей.
- Проверяй недоступность хранилища, границы буфера и повтор отправки при изменениях пути записи. Рассчитывай время удержания в буфере от постановки точки в очередь.
- При изменениях аналитики проверяй качество прогноза на отложенной по времени истории, влияние на задержку записи и совпадение предупреждений в панели с сохранёнными правилами.
- Соблюдай ограничения по доступу и сохраняй секреты вне Git. Реальные данные консультанта храни вне репозитория, пока владелец проекта не согласует их публикацию.

## Вычитка и проверка

- Для русскоязычной документации применяй `humanizer-ru` и `clean-user-facing-text`. При вычитке сохраняй точные требования, численные значения, имена файлов, примеры и договорённости.
- Для изменений прикладного кода применяй `clean-code-guard` после работы над кодом и перед коммитом. Запускай доступные проверки затронутого компонента и записывай фактический результат.
- Перед отправкой проверь состав коммита. Отправляй согласованные изменения в [Broad1e/diplom](https://github.com/Broad1e/diplom) и указывай, какие проверки прошли.
