# Архитектурные решения

| Тема | Статус | Обоснование и условия пересмотра |
| --- | --- | --- |
| Windows для агента | Согласовано | Целевая машина разработки и демонстрации работает под Windows. Агент запускается непосредственно на Windows. Сбор сначала проверяем на этой ОС. |
| Один администратор | Согласовано для MVP | Администратор видит все наблюдаемые серверы. Состав ролей и разграничение доступа пересматриваем по итогам ревью. |
| Охват прогноза | Согласовано | Прогнозируем показатели CPU, RAM, заполненности файловых систем и дискового ввода-вывода. На панели показываем прогноз перегрузки, предупреждения о возможных аномалиях и фактические отклонения. |
| Источник данных для испытаний | Согласовано | Синтетические ряды позволяют воспроизвести сценарии и проверить события с известным временем начала. При появлении реальных данных сначала оцениваем их состав, шаг и длину, затем сравниваем результаты. |
| Go, Python и React | Согласовано | Go обрабатывает непрерывный поток метрик. Python отвечает за подготовку рядов и расчёт прогнозов. React отвечает за интерфейс. Python остаётся вне пути записи измерений. |
| Порог со слайдером | Согласовано для MVP | Администратор сразу видит изменение отметок на графике. Пороги перегрузки и отклонения сохраняются отдельно. |
| Доставка при сбоях | Согласовано для MVP | Повторяем отправку в пределах ограниченного буфера в памяти. При перезапуске процесса возможна потеря неподтверждённых точек. Пять минут и численный лимит очереди проверим на стенде. |
| Пакетная запись | Рабочее решение | Сравниваем размеры пакета и таймеры сброса с записью отдельными запросами. Выбираем режим по устойчивой пропускной способности при допустимой задержке и полноте записи. |
| Чтение истории в Python | Рабочее решение | Прямое чтение позволяет передать окно измерений один раз. Альтернатива с передачей через Go упрощает зависимость от TSDB. Сравним время расчёта, расход ресурсов и задержку записи при активных прогнозах. |
| PostgreSQL и Redis | PostgreSQL входит в рабочую схему, Redis предварительный | PostgreSQL хранит настройки и последние расчёты. Подключение Redis зависит от того, покажут ли замеры повторяющиеся дорогие запросы. |
| TSDB | Открыто | VictoriaMetrics рассматриваем как кандидата. До выбора сверяем пакетную запись, получение исходных измерений, повторные записи и способ запуска на доступном стенде. Окончательный выбор согласуем с консультантом. |
| Модели и горизонты прогноза | Открыто | Начинаем с прогноза по последнему наблюдению. Сравниваем статистические методы по точности, предупреждениям и времени расчёта. В числе кандидатов EMA, методы Хольта и Хольта–Винтерса, ARIMA, линейная и полиномиальная регрессии. |
| Сокращение объёма истории | Открыто | Если понадобится отдельный эксперимент по экономии диска, проверим агрегацию старых данных с сохранением минимумов и максимумов. Оценим, какие свойства коротких перегрузок теряются при прореживании. |
| Среда разработки и стенда | Windows согласована, запуск серверных зависимостей уточняется | Разработка и проверка агента ведутся на Windows без отдельной виртуальной машины. Способ запуска хранилища проверим при выборе TSDB. Docker Compose можно использовать для воспроизводимого серверного окружения, если оно подходит для стенда. |

Изменения после ревью руководителя и консультанта заносим сюда вместе с причиной и связанными изменениями требований.
